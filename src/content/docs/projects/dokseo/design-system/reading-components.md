The image reader and the ebook reader are built from a handful of base pieces in `src/lib/components/`: a carousel, a dock, a chrome bar, a pure gesture classifier, pan-zoom math and a selection marquee. They're the general [pointer](/interaction/pointer-drags/), [gesture and marquee](/interaction/selection-marquee/) techniques packaged as domain-free components. How the viewers use them is on the [paged viewer](/projects/dokseo/image-reader/paged-viewer/), [continuous strip](/projects/dokseo/image-reader/continuous-strip/) and [reader chrome](/projects/dokseo/image-reader/reader-chrome/) pages.

## Carousel: the settle fallback

`Carousel` shows the current page with its neighbors beside it, and a swipe or a page turn moves them. When the turn is released, the slots ease to their resting place, which I call the settle, and the settle normally ends on `transitionend`. The keyed-slot mechanism is on [a keyed carousel](/svelte/keyed-carousel/). If `transitionend` never comes, a fallback timer ends the settle instead. The timer needs the slot's `transition-duration`, but the slot has `transition: none` until `.is-settling` is on it, and that class arrives with Svelte's next DOM update, not with the assignment to `motion`. Read inside the event handler that starts the settle, `getComputedStyle(slot).transitionDuration` is `"0s"`. So the timer is armed in an `$effect` on the settle: by then the class is there, and the effect's teardown clears the timer when `motion` leaves the settle, which replaced a hand-kept timer variable ([details](/svelte/keyed-carousel/#reading-a-computed-transition-that-a-state-class-switches-on)).

`settleFallbackMs` turns the value into milliseconds. Chromium reports it in seconds (`"0.18s"`), possibly as a comma list, so the function takes the longest and rounds to whole milliseconds, since `0.14 * 1000` is `140.00000000000003`. The timer fires at that duration plus `SETTLE_FALLBACK_MARGIN_MS` (220 ms), or at once when the duration reads as zero (`SETTLES_AT_ONCE`), because then no transition runs at all.

## Dock: how the sheet got its size

Dokseo, my manga and book reader, shows its captures on a phone in a dock below the page: a toggle button, and a panel that opens as a sheet. Before `Dock` was a base component, it was feature CSS in Dokseo, and its sizing went through three versions.

**A percentage on the aside.** The phone capture sheet was sized by `:scope.is-sheet { block-size: 40% }` on the `<aside>` itself, a flex item of the reader's column body. On iOS Safari, "Hide captures" left it at its open height: the toggle read "Captures 2", the list was gone, and a blank band of about 40% of the reader stayed below the toggle, so the page and its image never grew back. Chromium relaid it out correctly (dock 338px open, 33px hidden, page back to 811px), and I couldn't reproduce the stale height because WebKit wasn't installed and Safari's remote automation was off. So the cause I name is only the one path that differs, not an observed WebKit internal: a flex item whose own percentage block size is dropped by a class change, next to a sibling whose size depends on it.

**The size on the part that hides.** The fix moved the size to the slot that's shown and hidden, `:scope.is-sheet .panel-slot { block-size: 40dvh }`, and took `flex-1` off the slot. Its `flex-basis: 0%` in an auto-height column resolves as content and would override the block size, and a feature rule can't reset a utility's basis, because the utilities layer beats features. The dock itself became `auto` in every placement, and hiding sets `display: none` on the slot. Open, the dock was 371px (toggle plus 40dvh) where it had been 338px. I confirmed on iOS Safari that the sheet now hides and the page grows back. The rule is on [a dock that hides must be sized by its content, not by a class](/css/layout-quirks/#a-dock-that-hides-must-be-sized-by-its-content-not-by-a-class). When the dock became the base `components/Dock.svelte`, the rule became `.dock-sheet .dock-panel { block-size: var(--layout-sheet-height) }` in `src/lib/styles/components/dock.css`, with the token at `40dvh` and `.dock-panel` still without `flex-1`.

**Out of the flow.** A sheet laid out as a flex sibling of the page still resizes the page on every open, close and drag frame, and foliate re-paginates a chapter on each resize ([why](/ui-patterns/reader-layout/#a-bottom-sheet-that-shrinks-the-page-costs-a-reflowing-viewer-a-relayout)). So below the page the aside now keeps only the peek's room in the flow, and the open sheet is `.dock-drawer`, absolute over the page. What it covers goes back to the frame as a number through `cover`, and `ReaderFrame` passes that to `ChromeBar`'s `--chrome-bar-lift`.

Smaller fixes came with the drag handle:

- **The click after a drag.** The handle is both a drag target and a button, and with pointer capture the `pointerup` lands on it, so the browser fires `click` after every drag ([details](/interaction/pointer-drags/#a-drag-on-a-button-with-pointer-capture-still-ends-in-a-click)). `DockSheet` records whether the last release moved past the touch slop and ignores the next click unless its `detail` is 0, which is what a keyboard-made click has. So Enter and Space are never eaten by a stale flag.
- **Detents in pixels.** The drag math needs `--layout-sheet-height` and `--layout-sheet-height-tall` in pixels, and `getPropertyValue` returns `40dvh`. Registering the tokens would change them for every reader, so two hidden `.dock-probe`s take the token as their block size and are read with `bind:clientHeight` ([details](/css/tokens-at-runtime/#a-dvh-token-in-pixels-comes-from-a-probe-not-getcomputedstyle)).

## Gesture and GestureFeed

On a touch screen, the readers have to distinguish a tap, a double tap, a long press, a pan, a swipe and a pinch. That's done by a pure classifier: it takes the current state and one pointer sample and returns the new state plus what happened. The classifier is `gestureStep`, with `gestureDeadline` for its timeouts, in `components/gesture.ts`, and the host's timer is `GestureFeed` in `components/gesture-feed.ts`. After every `step`, `GestureFeed` arms one timer for the next moment a tick could change anything, so no timer runs while nothing waits, and a tick that lands early does nothing. It takes a `Clock`, so its spec advances a fake one instead of waiting. The reducer has no tap zones of its own: it calls the caller's `waitsForDoubleTap(at)`.

`GestureFeed` is fed from the caller's own pointer handlers rather than attaching listeners itself. Svelte 5 delegates pointer events at the root, so a listener attached directly to the element would fire before the host's handlers, and which gesture wins would depend on mount order. Fed from the host, the order is written in one function. The marquee below works the same way.

## PanZoom and the zoom surface

The zoom math is `components/pan-zoom.ts` and the transform is the `.zoom-surface` class. They're one pair: the math is written for `transform-origin: 0 0`, and the CSS default is the center, which adds a shift the math doesn't model. A caller that draws a viewport some other way has to keep the origin at `0 0` itself.

A wheel zoom starts from the wheel event's delta, which isn't always in pixels: `deltaMode` can be lines or pages. A mouse wheel in Firefox reports lines, but only when `deltaMode` is read before the deltas. `wheelPixels` reads a delta of any mode as pixels, a line being `WHEEL_LINE_PX` (16px), and `wheelZoomFactor` turns the pixels into a zoom factor ([deltaMode is not always pixels](/interaction/wheel-and-touch/#deltamode-is-not-always-pixels)).

## MarqueeSelection

Selecting a region of a page, to recognize its text, is a drag that draws a box: the marquee. Its pointer handlers belong to the base `MarqueeSelection`, and the readers' `SelectionLayer` exports the same names and forwards each call to it. The host calls them from its own handlers, so the rule that a pan wins over a selection lives in one function, not by mount order ([a shared gesture layer exports handlers](/interaction/pointer-drags/#a-shared-gesture-layer-exports-handlers-it-does-not-attach-them)). The playground's marquee section forwards the same way.

Touch never reaches `pointerdown`. The viewer sends touch through `GestureFeed` to `gestureStep` and turns its results into `beginAt`, `extendTo`, `endAt` and `abandon` ([a gesture classifier drives the marquee by calls](/interaction/selection-marquee/#a-gesture-classifier-drives-the-marquee-by-calls-not-by-events)). They end in the same conclude step as the mouse's `pointerup` (see below), so a region is measured and committed by one path. `endAt` concludes with the touch slop and never calls `onclick`, because the classifier has already reported every tap, though `onend` still reports the `click` for the trace. The frame takes the touch pointer's capture itself at `pointerdown`, since the marquee never receives it.

`followScroll(by)` is for a drag over a scrolling strip: the anchor moves by the scroll delta so it stays on the content it was pressed on ([a marquee over a scroller](/interaction/selection-marquee/#a-marquee-over-a-scroller-anchor-by-scroll-delta-and-pin-the-window)).

All of that drag logic used to sit in the component's script. Now it's a view model, `MarqueeDrag` in `components/marquee-drag.svelte.ts`, which holds the drag's state (the anchor, the pointer, the scroll traveled, the kept selection) and has a method for each step: `press`, `move`, `lift` and `cancel` for the forwarded pointer events, `beginAt`, `extendTo`, `endAt` and `abandon` for the driven touch drag, and `followScroll`, `keep`, `reset` and `dismiss`. Every ending goes through one private conclude step, which classifies the end with `marqueeEnd` and reports it. `MarqueeSelection` builds one `MarqueeDrag` and passes it the surface and the callbacks as functions, so its spec runs in bare Node. The component keeps what needs the real DOM: the elements, pointer capture, `preventDefault` and the markup. The split is the one on [what a view model still holds](/projects/dokseo/architecture/data-components-and-view-models/#what-a-view-model-still-holds).

## BreakpointProbe

The readers switch structure (side dock or bottom sheet) at a breakpoint token, which no size query can read. `BreakpointProbe` renders a hidden element as wide as the token and binds its width, and the caller compares its own width with it ([a breakpoint token measured by a probe](/css/tokens-at-runtime/#a-breakpoint-token-measured-by-a-probe)).
